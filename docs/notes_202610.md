# 电控学习笔记（2026.10）

## 10-05 BSP

### YAGNI

它背后是一条工程原则：YAGNI（You Aren't Gonna Need It）——只为真实存在的需求付复杂度。时钟计算目前只有 SetPeriod 一个用户，独立助手函数就是过度设计；哪天 SetDutyRatio 或其他地方也需要定时器时钟了，再提取不迟（到时候是「重构出助手」，不是「一开始就别加」）。

### PWM 分频

分频：apb1 42起，apb2 84起

- 预分频 = 1：tim 不动
- 预分频 ≠ 1：tim × 2

```c
const uint32_t ppre = on_apb1 ? (RCC->CFGR & RCC_CFGR_PPRE1)
                              : (RCC->CFGR & RCC_CFGR_PPRE2);
const uint32_t div1 = on_apb1 ? RCC_CFGR_PPRE1_DIV1 : RCC_CFGR_PPRE2_DIV1;
const uint32_t tim_clk = (ppre == div1) ? pclk : pclk * 2;
```

这里 PRE 和 DIV 是两个缩写：

- PRE = Prescaler（预分频器）。PPRE1/PPRE2 是 RCC 的 CFGR 寄存器里的两个字段（各 3 个比特），分别记着 APB1 / APB2 总线的分频比。硬件模型：CFGR 是时钟系统的"配电箱"，里面有几格拨码开关，PPRE1 那格决定 APB1 降几档速。
- DIV = Divider（分频）。RCC_CFGR_PPRE1_DIV1 是 HAL 头文件里写好的常量，意思是"分频比 = ÷1"对应的编码（这 3 比特 = 0b0xx 时表示不分频）。HAL 还给出了 DIV2、DIV4、DIV8、DIV16 一整套，就是拨码开关的各档位。

逐行翻译这三行在干什么：

1. `RCC->CFGR & RCC_CFGR_PPRE1` —— 按位与：把配电箱读出来，用掩码只保留 PPRE1 那 3 个比特，其他位清零，得到"APB1 现在拨在哪一档"。
2. `div1 = RCC_CFGR_PPRE1_DIV1` —— 取出"÷1 档"的编码备用。
3. `ppre == div1 ? pclk : pclk * 2` —— 判断：拨在 ÷1 档 → 定时器时钟 = PCLK（不翻倍）；拨在别的档 → ×2。

## 10-09 modules——电机

- 句柄：档案袋：用一个结构体变量代表"某个资源/某台设备"
- ecd 就是电机转子当前位置的"刻度盘读数"：机械角度(°) = ecd / 8192 × 360
- DJIMotorList 用指针登记
- `DJIMotorList[0][i] ?` 意味着 `if (DJIMotorList[0][i] != nullptr)`，没注册填 0
- CAN：两条总线，每条总线上两个数据帧，每个数据帧对应 4 台电机的电流
- 解析：按照规定的协议把信息取出来并重新排布
- 反馈帧：01 ecd，23 spd，45 电流（要 × 比例），6 温度，7 保留
- 电机：电机轴 / 输出轴 = 减速比
- `MotorControlModeType controlMode;` 和 `int a;` 是同一语法。MotorControlModeType 是类型名（和 int 平级），controlMode 才是变量名。

## 10-11 电机

- 读函数声明的规则是"返回类型 + 函数名(参数)"
- Instance：单例。所以教科书单例必须配合：把构造函数（和拷贝构造、赋值运算符）放进 private:，让这两行编译不过。至此，"创建一个 DJIMotorHandler"这个动作全程序只剩 Instance() 一个合法入口，而它内部又被 static 标志位锁死——两层合起来才是真·单例。
- 子类继承：
  1. 表达的是一种 is-a（是一种）关系
  2. 白拿父类的全部非私有成员
  3. `= 0` 意味着纯虚函数——父类只给接口不给实现。后果：DJIMotor 是抽象类，你写 `DJIMotor m;` 直接编译错误，它只能被继承。
  4. 构造顺序：① 先跑 DJIMotor() ← 父类构造：controlMode = RELAX_MODE，各成员清零；② 再跑 M2006() ← 子类构造：maxCurrent=10000，配 PID，调 setOutput()
  5. 有虚函数的类，析构必须 virtual。
- DJIMotorList：指针数组（不同电机大小一样，DJIMotor 抽象类无对象），指针永远指向对象

## 10-13 BSP 代码

### bsp_can

**can_init：**

- CAN 过滤器配置：设置结构体 → HAL 配置结构体给对应 can1 → 使能 can1 → 使能各种中断 → 规定主从关系 → 使能 can2 → 使能 can2 中断

**can_transmit：**

- 判断输入数据有效
- 判断邮箱有空
- 发送：设置帧头，HAL 函数发送
  - `HAL_CAN_AddTxMessage(hcan, &tx_header, msg, &mailbox);`
  - 参数 mailbox 里存放此条信息使用的发送邮箱的编号，而非存数据本身

**can 接收中断函数：**

- 设帧头，数据空参数
- 检验接收是否成功（这一步接收把实际参数放进去 + 检验）
- 检验标准帧
- 检验 id
- 把信息存入，更新电机反馈
- can_init 里自动打开发送和接收开关

### bsp_pwm

- pwm_init / pwm_start / pwm_stop
  - Init：一次打开多个要用的 pwm
  - start/stop：打开/关闭某一个特定的 pwm
- pwm_SetPeriod：这次用的都挂在 apb2，预分频为 3，arr = pclk × 2 × period - 1
- pwm_SetDutyRatio（输入 0-1 之间的值）：pulse = dutyratio × (arr + 1)

## 10-15 BMI088 代码

- calibrate 零飘：采样次数，设读取变量，总量/平均量归零，循环采样，计算平均值，判断有效性/置错
- temperaturecontrol：读取温度，调用 pid，限制范围，结果输给 pwm 调电流大小，置错（芯片 id 检验错误）
- VerifyAccChipID：设收信息变量，读 id，休眠（1），判断第二个字节对不对
- VerifyGyroChipID：同上
- VerifyAccData：设收信息变量，读信息，判断是否全 0 / 全 1，置错
- VerifyGyroData：同上
- WriteReg：位与写标志符，拉低片选，发送 + 判断通信是否成功，拉回片选，休眠（1）
- ReadReg：判断地址是否有效，无效返回，有效数组清零，置读 bit，拉低片选，发送地址并判断是否成功，如果是加速度，读第一个字节并丢弃，继续读并判断是否成功，拉回片选，休眠（1）
- config：休眠（10）等待系统稳定；加速度计初始化；陀螺仪初始化
- ReadAccData：判断地址是否有效，设置放原始信息的空数组，调用 ReadReg 读信息，处理信息，放入 data（换算）
- ReadGyroData：同上，最后一步处理零漂
- ReadAccTemperature：同上，但信息处理方式不同

### 温度换算

raw_temp 翻译成摄氏度，两个宏就是翻译汇率，都定义在 BMI088.hpp 里：

```c
#define TEMP_UNIT 0.125f   // 每 1 个 raw 计数 = 0.125 ℃
#define TEMP_BIAS 23.0f    // raw = 0 对应的实际温度 = 23 ℃
```

实际温度(℃) = raw × 0.125 + 23
